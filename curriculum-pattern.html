Enterprise GIS Curriculum Pattern

An adaptable design for teaching ArcGIS Enterprise in a college or university GIS program: one core administration course, one advanced geodata module, and four short modules that carry server skills into neighbouring courses and streams — all running on a single shared virtual server, with every reading and lab pointing to a verified free or education-licensed resource.

N0 · 2 km 1 core course · 1 advanced module · 4 program modules Cert-aligned (EAEP / EGMP) Companion to the Enterprise GIS Educator Hub

Design stance

Five decisions that shape everything below

1 · Architecture-led, not click-path led

Students learn why organizations run a portal — multi-tier architecture, services, governance — before they learn where buttons are. The pedagogy literature (Bearman et al. 2016) and the GIS&T BoK CP-04-014 Web GIS outcomes both push this way, and it survives version churn.

2 · Students run the org, not just use it

The differentiator vs. every ArcGIS Online course: students hold admin roles. Teams operate their own portal scenario — members, roles, security policy, services — the way Penn State's GEOG 865 Cloud & Server GIS has students run their own server.

3 · Certification domains as the outcome spine

Course outcomes map to the domain weights of Esri's Enterprise Administration and Geodata Management exams — a defensible, external, workforce-validated skills inventory (grads sit the exams years later, but the map is the point).

4 · Upgrade existing slots first

Most GIS programs already have the hooks — a GIS servers / web GIS course, a spatial database course, a web mapping or cartography course, a GIS programming course. The core course below is the next edition of the first; versioning deepens the second; the modules slot into the rest. New-course paperwork is minimized; the BCIT GIST 8109/8132 pairing is a Canadian precedent.

5 · One VM, reset every term

Everything runs on one base deployment (~8 vCPU / 32 GB) in the institution's data centre or cloud tenancy, built with Enterprise Builder or rebuilt per term via PowerShell DSC, backed up with webgisdr. Budget = education agreement + VM hosting.

Assumptions (adjust to your institution)

14-week semester; ~2 h seminar + 3 h lab per week for the core course; graduate-certificate level with intro GIS and a database/SQL course as prerequisites. Delivery pattern, hours, and course codes are placeholders for the faculty to set.

Course A · Core · 14 weeks

Enterprise GIS Administration

Typically the next edition of an existing GIS-servers or web-GIS course. Students deploy, secure, and operate a complete ArcGIS Enterprise, publish and tune services on it, stand up an enterprise geodatabase behind it, and finish by running a small organization on it. Prerequisites: introductory GIS; a database/SQL course; basic OS comfort. Suggested text: Getting to Know ArcGIS Enterprise (Esri Press, 2025) — the first Esri Press book on the product, written partly for educators.

Learning outcomes · mapped to EAEP domains & GIS&T BoK

  1. Explain multi-tier web GIS architecture and the role of each Enterprise component. BoK CP-04-014
  2. Deploy and license a base ArcGIS Enterprise deployment on a virtual server. EAEP: Deploy 34%
  3. Administer members, groups, roles, and security — including SSO with institutional identity. EAEP: Content & users 26%
  4. Publish, tune, and troubleshoot map, feature, and hosted services. EAEP: Troubleshoot 18%
  5. Create an enterprise geodatabase and operate versioned editing workflows. BoK DM-01-001
  6. Automate backup, monitoring, and rebuild tasks. EAEP: Maintain 22%
  7. Design and defend a small enterprise GIS for an organizational scenario. Capstone

Assessment

Weekly labs (best 9 of 11)35%
Admin runbook — living ops document, built week by week15%
Midterm practical — broken-portal troubleshooting, timed15%
Team capstone — "run the org" + presentation25%
Concept quizzes (architecture, licensing, security)10%

The runbook is the signature assessment: each student maintains the operations manual for their deployment — exactly the artifact an employer wants to see, and the habit the Governing ArcGIS in Higher Ed series says campuses lack.

Course B · Advanced · 7 weeks

Enterprise Geodata Management

A half-semester deepening — run as an elective, or as the back half of the program's spatial database course. Where Course A treats the geodatabase as one week's stop on an admin tour, Course B makes it the subject, aligned to the EGMP certification domains (design, loading, versioning, archiving, tuning). Supporting text: Focus on Geodatabases in ArcGIS Pro; skills inventory: the official EGMP learning plan.

Program modules

Carrying server skills into the other programs

Each module is 2–3 weeks of an existing course, consumes the same shared portal, and assumes Course A is running somewhere in the school — so the platform is always administered, and other programs just use it.

Shared Notebooks Analytics stream · 3 weeks

  • Wk 1: Notebooks as the analytics workbench — runtimes, portal items, sharing (get started with notebooks).
  • Wk 2: ArcGIS API for Python against portal layers; a reproducible ETL notebook — directly extends an analytics stream's pipeline focus.
  • Wk 3: Scheduled notebooks as lightweight automation; publish results back as hosted layers (Notebook Server docs).

Imagery Hosting Remote sensing · 2–3 weeks

  • Wk 1: Image services vs static rasters; mosaic datasets (Image Server docs).
  • Wk 2: Publish and serve a drone/satellite collection; dynamic processing with raster functions.
  • Co-curricular: the free ArcGIS Imagery MOOC as whole-class enrollment; browser-only imagery tutorial as the on-ramp.

Consuming the Portal Web mapping · 2 weeks

  • Wk 1: Web maps in the Enterprise Map Viewer — smart mapping, pop-ups, filters (Map Viewer tutorial).
  • Wk 2: Apps on portal services; the sharing model from the consumer side. Text alignment: Getting to Know Web GIS.

REST & Admin Automation GIS programming · 2 weeks

  • Wk 1: The ArcGIS REST APIs — every service and admin operation is an endpoint; query and geoprocess from code.
  • Wk 2: Scripted administration with Python — create users, audit content, reset a lab org (model scripts: Esri education admin scripts).

Logistics

Infrastructure, accounts & the per-term rhythm

What campus IT provides

  • One VM in the institution's data centre or cloud — start at 8 vCPU / 32 GB / 150 GB SSD, Esri's Enterprise Builder recommendation for a single machine (48 GB if 3D/scene layers are taught; no GPU on this VM — see the sizing guide). Mind the 4-core ArcGIS Server license minimum when assigning vCPUs (licensing whitepaper — confirm current terms with Esri Canada).
  • PostgreSQL on the same VM or a small second one — the no-extra-cost DBMS for the geodatabase labs.
  • SAML SSO against college credentials with new-member defaults, so accounts appear on first login (SAML docs). No SCIM yet — end-of-term cleanup is a Python script, which the programming module conveniently teaches.
  • Term rhythm: snapshot + webgisdr backup at term end → restore clean baseline → rebuild drift with PowerShell DSC/Chef if needed. Rehearse cheaply with Chef Test Kitchen (~12 GB local VM).
  • Students: Creator user type by default (includes Pro Basic); Professional where Pro Standard tools are needed; custom "admin-lite" roles for Course A teams.

Faculty preparation & sustainability

  • Instructor prep path: the bundled e-Learning (Getting Started → Security → EAEP learning plan), with the instructor-led Administration Workflows class as the paid fast-track via Esri Canada.
  • Keep current through the Enterprise blog and Esri Community Education; present the build at the Esri Education Summit or the Canadian GIS in Education and Research community.
  • Review cycle: re-validate the week plan against each Enterprise release (currently 12.1); the architecture-led design means most weeks survive version churn untouched.
